# universal-paywall-site

The static marketing + documentation site for
[Universal Paywall](https://github.com/mnemonik-dev/universal-paywall) — the
open-core, non-custodial payment rail that attaches to creator platforms
**without forking them**.

Built with [Astro](https://astro.build) in fully static mode: no server, no
third-party requests, no analytics, no external fonts. Deployable to any static
host (or IPFS).

## Run / build

```bash
npm install
npm run dev        # local dev server (http://localhost:4321)
npm run build      # static output → dist/
npm run preview    # serve the built output locally
```

## Deploy

**GitHub Pages (automatic):** `.github/workflows/deploy.yml` builds and publishes
the site on every push (and via manual *Run workflow*). It uses
`actions/configure-pages` to inject the correct `SITE_URL`/`BASE_PATH`, so it works
both at `https://<org>.github.io/universal-paywall-site/` and behind a custom
domain with no config change. If the first run fails on Pages enablement, enable
**Settings → Pages → Source: GitHub Actions** once and re-run (private repos need a
paid plan for Pages).

**Your own server:** build + rsync in one step, then serve `dist/` with any static
server (`deploy/nginx.conf` is a ready-made server block):

```bash
DEPLOY_HOST=example.com DEPLOY_USER=deploy DEPLOY_PATH=/var/www/universal-paywall \
  ./scripts/deploy-server.sh
```

Internal links honor `BASE_PATH` (see `withBase()` in `src/lib/site.ts`) — leave it
unset for root deploys.

## Where content comes from

The site **paraphrases the main repo's docs — it never invents claims**. The
authoritative sources are:

| Site content | Source of truth (in `mnemonik-dev/universal-paywall`) |
|---|---|
| Positioning, rail diagram, package map | `README.md`, `CLAUDE.md` |
| The six attachment patterns | `work/creator-platform-integrations/integration-patterns.md` |
| "tested" badges + Verify sections | `work/creator-platform-integrations/testing-plan.md` |
| Admin env reference + prerequisites | `packages/integrations/deploy/README.md` |
| Per-platform quickstarts/caveats | `packages/integrations/deploy/<platform>/README.md` |
| PeerTube specifics | `packages/peertube-plugin/README.md` |
| Build-a-new-integration | `packages/integrations/INTEGRATION-PLAYBOOK.md` |

Repo links are generated by `src/lib/site.ts` (`REPO_URL` + `repoLink()`); change
the repo or branch there once.

## Adding an integration

Everything on `/integrations` (the grid, the per-platform pages, the home cards)
renders from data. To add a platform:

1. Add one record: `src/content/integrations/<slug>.yaml` (the schema is
   documented in `src/content.config.ts` — name, vertical, pattern, metered
   event, attach surface, quickstart, verify, caveats, recipe link).
2. That's it. The build generates `/integrations/<slug>` with the full §4.4
   template, adds the card to the grids, and derives the vertical filter — no
   other code changes.

Only PeerTube carries extra hand-written content
(`src/components/PeertubeExtra.astro`), rendered below the shared template on
its page — it's the first-class flagship integration.

## Structure

```
src/
  content.config.ts            # integration record schema (zod)
  content/integrations/*.yaml  # one record per platform — drives everything
  lib/site.ts                  # repo URL, doc index, pattern labels
  layouts/Base.astro           # head, theme bootstrap, header/footer
  components/                  # IntegrationCard, RailDiagram (inline SVG),
                               # CodeBlock (copy button), Callout, Badge, …
  pages/                       # /, how-it-works, integrations(+[slug]),
                               # creators, admins, developers, docs, faq
  styles/global.css            # design tokens (light/dark), AA contrast
```

## Conventions

- **No secrets, ever** — quickstarts use `0x…` / `FACILITATOR_API_KEY=…`
  placeholders only.
- **No third-party anything** — self-contained assets, system fonts, and the
  theme preference lives in `localStorage`.
- **Trademark caution** — platform cards use names + neutral styling, not
  official logos.
- Creator-facing copy defaults to **"support / tips / get paid"**, not
  "paywall" — paywalling is a mode, not the headline.
